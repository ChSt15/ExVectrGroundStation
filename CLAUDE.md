# ExVectr ground station

Python core (asyncio, headless) plus a browser GUI that records, visualises and replays data from the model Starship, and carries the virtual radio (RC channel state to the vehicle). Part of the ExVectrStarship workspace; this folder is its **own git repository**. Workspace-level rules live one folder up (`../CLAUDE.md`, `../docs/safety.md`, `../docs/system-architecture.md`).

**The spec is `docs/ground-station-design.md`** (interfaces, packet model, log format, API, GUI, task plan in section 9). Follow its names, signatures and layout. User decisions in its section 10.1 are binding and override anything else in the doc. Read only the sections your task needs, plus section 1 (safety).

## Safety rule (review rule)

The ground station **never makes control, mission or safety decisions** for the vehicle. It records, displays, and sends only these things (design 1.4, decisions 10.1-9 and 10.1-10): (a) RC channel state under the control-lease rules, (b) whitelisted events and requests after operator confirmation (commands: `hold`; link-module actions: `danger`; requests since user 2026-11-19), (c) automatic requests only where a setting enables them: `[requests] auto_home` (default true), home only, on the T-5 trigger (reliable-transport-design 8.1); never from replay or without a live source; results are display data only; retries are done by the transport, not decided by the GS, and (d) **TEMPORARY: legacy telecommands from a configured whitelist (user 2026-11-20, explicit approval; port 0x7F, `telecommand/`, `docs/telecommands.md`). THIS THIRD UPLINK IS TEMPORARY AND MUST BE DELETED WHEN THE FLIGHT SOFTWARE'S T9b LANDS (TODO: remove the `telecommand/` package, `[telecommands]`, `telecommand.*` API ops, `exgs tc`, the GUI panel `telecommands` and the `Telecommand` packet; the list is in `docs/telecommands.md`).** A change that makes the GS compute a command, gate an action on vehicle state, send anything other than `UP` types (through the RC sender, the request sender or the telecommand sender), send a request or event automatically other than `auto_home`, make the GS itself decide a retry or repeat, repeat or retry a telecommand, widen what the request or telecommand path accepts, or persist RC state is a **safety change and needs user approval**. Consequences in code:

- Panels and the API show vehicle-reported values only. No optimistic UI, nothing inferred from sent commands.
- The only uplinks are the RC state (`rc/`), the whitelisted REQUESTs (`requests/`, `docs/requests.md`) and, TEMPORARILY, the whitelisted legacy telecommands (`telecommand/`, `docs/telecommands.md`). No raw-send API. No other legacy one-shot telecommands. A request is sent only on a deliberate confirmation (GUI hold 1 s, plus a modal with a 2 s disabled button for `danger`; CLI `--confirm ACTION`, plus `--i-understand-the-link-stops` for `danger`), or automatically only as the enabled `auto_home` home request, never in replay, never from a source that is not connected, control hosts only, at most one new request per 500 ms per client host. `LINK_UPLOAD_MODE` and `LINK_REBOOT` are `danger`: the Router and the ship radio node always obey them (workspace safety.md 2.5 exception), the radio link stops or restarts (a reboot of the ship radio node in flight interrupts RC for seconds). The GS does not interpret actions and shows the vehicle's ACK status exactly as reported (never an assumed success).
- A telecommand is sent only on a deliberate confirmation (GUI hold 1 s, CLI `--confirm NAME`), **exactly one frame per confirmation: no retry, no repeat, no ACK (this applies to the TEMPORARY legacy telecommands only; the safe transport's retries are the transport's, not the GS's)** (the vehicle de-duplicates nothing and `SimulationMode` toggles), only to a connected route (vehicle USB first, else the Router), control hosts only, never in replay, at most one per 500 ms per client host. The GUI and CLI show the time it was sent and nothing about the outcome: the result is only what the vehicle reports in `VehicleStatus` (the simulation state is never assumed).
- The mission status bar and every panel show vehicle-reported values only.
- The GS is slave while the Pocket's RC state arrives (shows it, sends nothing) and master only by explicit user choice (the lease); master sends to every connected `rc_role = "control"` source, and the GS adds no rejection of its own (decision 10.1-8).
- RC state is never persisted. After a start every control is at its safe default (and every locked control locked) and nothing is sent until a client takes the control lease. When the lease holder disappears, or a keepalive lease is not renewed within its idle timeout (max 9 s), the core stops sending (decisions 10.1-1, 10.1-7). A locked control (`lock` in the radio config, SD) cannot leave its default without a deliberate unlock (10.1-6).
- No simulator, autopilot, arm macro or command sequencing in this repo.

## Layout and layers

`src/exvectr_gs/`: `packets/` (registry, text codec, type declarations) , `core/` (bus, state store, history, clock, config, app wiring), `wire/` (Frame, Framer, WireProfile protocols and profile plug-ins), `sources/` (Source, FakeSource, later serial), `recording/`, `replay/`, `rc/`, `requests/`, `telecommand/` (TEMPORARY), `update/` (self-update, `docs/updating.md`), `api/`, `cli/`. Frontend in `web/` (plain ES modules, vendored pinned libraries, no build step, must work offline). Full tree: design section 8.1.

Keep the layers strict so each can be replaced later: source -> framer / wire profile -> packet registry -> codec -> bus / state store -> API -> panels. **Wire-format knowledge lives only in a wire profile plug-in.** Everything above it sees semantic `Packet` objects. Logs are semantic text and stay readable after the wire format changes.

User-facing names (decision 2026-11-20): node 2 is the **Router**, node 3 the **ship radio node** (`docs/glossary.md`); packet and identifier names keep the old spelling.

Status: self-update done on `feature/update-button` (`[update]`, `update.*` ops with guards, exit code 42 + `start.sh` restart loop, `exgs update`, GUI Software tab, `docs/updating.md`, `docs/install-frame.md`; not a vehicle uplink; userspace pyusb USB transport for the Frame on `feature/usb-transport`: `transport = "serial"|"usb"|"auto"` in `[[source]]`, `sources/usb_cdc.py`, `docs/usb-transport.md`; same frames, only the byte transport). T1 to T8 done (packet model and fake source; recorder, log reader/index/library and the offline `exgs log` tools; API server and read-side CLI; replayer; serial source and the pty fake vehicle; GUI shell and data panels and the 3D view with its config-driven model, `docs/gui.md`; RC controller with leases, 25 Hz sender, core-held momentary release and mirror/conflict detection, `docs/radio.md`). T9 (virtual radio widget, `web/app/radio/`) is done on `feature/virtual-radio-widget`, with two user decisions of 2026-11-19: the SD motor-enable switch sits behind a generic per-control `lock` (`rc.unlock`/`rc.lock`, padlock in the GUI, `--unlock` in the CLI) and the 600 s timed lease is replaced by the connection lease (GUI, `exgs rc session`) and a keepalive lease (one-shot CLI commands, idle timeout 5 s, max 9 s). The real wire profile `exvectrnet-1` (ExVectrNetwork stream frames, heartbeats, generated `exvectr_packets` from the submodules `lib/ExVectrPackets` and `lib/ExVectrNetwork`) is implemented, with the `exvectrnet-1` mode of the pty fake vehicle; the temporary `provisional-1` still works. The ground station also sends its own 1 Hz node 0 heartbeat on every connected `exvectrnet-1` serial source (information only, independent of RC leases; `docs/wire-profiles.md`). RC master/slave (user decision 2026-11-19, 10.1-8) is done on `feature/rc-master-slave`: slave (Pocket's `RC_STATE` arriving, nothing sent) is automatic, master is the explicit lease, allowed while the Pocket is active (warning), and sends to every connected `rc_role = "control"` source including the Router; the Pocket side always rejects, the GS never does. The RC controller is safety-relevant: read `docs/radio.md` before touching `rc/`. The REQUEST sender (user decision 2026-11-19, 10.1-9; branch `feature/request-sender`: `requests/`, `exgs request`, the Requests panel, `docs/requests.md`) is the second uplink and equally safety-relevant: read `docs/requests.md` before touching `requests/`. `feature/ops-and-telecommand` (user decisions 2026-11-20): the TEMPORARY telecommand sender, the mission status bar, `LINK_REBOOT`, the raw sensor panel, the power block of the link panel and the flap chamfer fix. The ExVectrPackets pin is at `53a7020` (**local-only** commit, branch `feature/split-reset-zero` of the flight software's copy; schema hash 0x761D5378; contains `LINK_REBOOT` = 11, `LINK_CONFIG` port 0x04, `CALIBRATION` port 0x93, `AIR_POSE.pos` as i32 at 1 mm, the `VEHICLE_STATUS` flags `UART_PEER_SEEN` and `ZEROING`, and the air packets `AIR_ACTUATORS` 0x22 (two samples per frame, mapped to two `Actuators` + `FlapState` sets) and `AIR_MISSION` 0x23); a node on another schema hash stays flagged as a mismatch until it is reflashed. `feature/zero-estimators` (user request 2026-11-20): telecommand `ZeroEstimators` (type 10, float `duration_s`), `SystemReset` relabelled (no longer zeroes the estimators), amber ZEROING cell in the status bar from the vehicle flag (`VehicleStatus.zeroing`, real data with the 53a7020 pin). The raw sensor panel computes calibrated values from `CALIBRATION` (display only). `feature/legacy-log-converter` (2026-11-20): `exgs log import-legacy` / `tools/convert_legacy_log.py` convert the old ExVectrController CSV logs to `.exlog` with a `LegacyRow` packet holding the original columns (`docs/legacy-logs.md`). `feature/callouts` (user request 2026-11-20): display-only audio callouts and toast notifications in the GUI (`web/app/callouts/`, Operations dock tab Callouts, `/config/callouts.json`, `docs/callouts.md`); sends nothing to the vehicle, off in replay by default, never the only warning. `feature/quit-button` (user request 2026-11-21): `core.quit` op, `exgs quit --confirm` and the Software tab Quit button (hold 1 s) stop the core cleanly with exit code 0, no restart; not a vehicle uplink (`docs/updating.md`). `feature/view-scale` (user request 2026-11-21): display-only GUI settings UI scale and 3D resolution (Operations dock tab Display, `docs/gui.md`) and smoothing of the 3D target position (never used for reported values); nothing sent to the vehicle. `feature/target-attitude` (user request 2026-11-21): the ExVectrPackets pin is now `18b6884` (schema hash 0xBFF82392, branch `feature/setpoint-attitude`, on GitHub), `MissionState.sp_q` from `MISSION` / `AIR_MISSION`, and ghost target-attitude axes plus an attitude-error readout in the 3D view (display only, `docs/gui.md`). `feature/audio-clips` (user decision 2026-11-21): callouts speak pre-recorded Piper clips (`en_GB-northern_english_male`, CC-BY-SA 4.0, `web/audio/`, `tools/generate_voice_clips.py`, optional extra `voice`) instead of browser TTS by default; Voice setting Recorded / Browser voice / Beeps only; display/audio only. `feature/callout-and-target-fix` (user request 2026-11-21): `Mission beginning` callout, phase callouts only while the mission is Running, and a second-order follower for the smoothed 3D target (`docs/gui.md`, `tools/analyse_target_smoothing.py`); display only.

## Setup and commands

```bash
git submodule update --init                                    # lib/ExVectrPackets, lib/ExVectrNetwork (generated packets, wire vectors)
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'     # Python 3.11+
.venv/bin/pytest                                               # all tests
.venv/bin/ruff check src tests tools && .venv/bin/ruff format --check src tests tools
.venv/bin/exgs core --config config/gs.example.toml            # fake source, 1 Hz summary (Ctrl-C to stop)
.venv/bin/python tools/run_js_tests.py                         # GUI unit tests (node --test, or headless Chromium if node is missing)
.venv/bin/exgs status --json                                   # client commands talk to the running core (docs/api.md)
.venv/bin/exgs schema --markdown > docs/packet-types.md        # regenerate after changing packet types
```

Run ruff only on `src tests tools` (it would also reformat code blocks in the Markdown docs). Runtime dependencies: `aiohttp`, `pyserial`, nothing else. No hardware is needed for development: use the `FakeSource` (`kind = "fake"`).

## Conventions

- SI units, time as `int` nanoseconds (JSON to clients uses float seconds). World frame NWU, quaternion `[w,x,y,z]` body -> world (workspace `CLAUDE.md`).
- Packet types are declared once in `packets/defs/`. Every field is optional (`None` = not supplied). Adding a field is backward compatible. Removing, renaming or changing a unit increments `version`.
- Docs rule: docs in `docs/` are versioned with the code and updated in the **same branch**. `docs/packet-types.md` is generated and a test checks it is current.
- Tests live with the code: `tests/unit`, `tests/integration`. Run the full suite and ruff before reporting a task done.

## Git workflow

`master` (released), `Development` (integration), `feature/<name>` cut from `Development`. Merge the latest `Development` into the feature branch and re-test before merging back. Never push or merge into `Development` or `master` without the user's approval.
